# The Problem

Businesses face supply chain disruptions every day - but **don't know the financial impact until it's too late**.

- A delayed supplier for **15 days** can trigger cascading losses across revenue, margin, and procurement
- Finance teams rely on gut feel or spreadsheets - no real-time calculation
- Commodity price signals (aluminum, packaging, energy) are public but **never connected to company financials**
- By the time a response is evaluated, the cost window has already closed

> **$648,000 revenue at risk** from a single 15-day logistics disruption - for a mid-size beverage company

</Slide>

<Slide tab="solution">

# The Solution

**MarginGuard** is a real-time supply chain risk platform that calculates the exact financial exposure from a disruption - before you decide how to respond.

- **Deterministic financial engine** - no LLM guessing; every dollar is traceable to inputs
- **Scenario modeling** - compare 7-, 15-, and 30-day disruptions instantly
- **FRED integration** - live commodity prices (aluminum, corrugated, energy) from the Federal Reserve mapped to your components
- **Nemotron intelligence** - NVIDIA LLM classifies news articles and ranks qualitative response options
- **Response comparison** - doing nothing vs. alternate supply, with exact cost/benefit ($19,500 extra cost → $187,500 net benefit)

</Slide>

# Architecture

```
FRED API (Federal Reserve)
        ↓
  Backend FRED Client          NVIDIA Nemotron
  (retry / timeout)                  ↑
        ↓                     Intelligence API
  DynamoDB Cache                     |
  (7-day TTL)              ──────────┘
        ↓
  Economic Signal Detection
        ↓
  Financial Engine (TypeScript · BigInt · deterministic)
        ↓
  Node.js API (Lambda-ready · Zod validation)
        ↓
  React Frontend (Vite · Three.js · Framer Motion)
        ↓
  AWS: Cognito · DynamoDB · S3 · CDK · Amplify
```

**Key design principles:** money in integer cents end-to-end · no LLM in financial path · transparent source labeling

</Slide>

<Slide tab="challenges">

# Challenges

- **Determinism vs. AI** - separating the financial engine (must be exact) from Nemotron intelligence (qualitative only); model evidence must be an exact substring of submitted text
- **FRED data reliability** - FRED returns `"."` for missing observations; retry logic with exponential backoff (3s, 8s) and 10-second transport timeout
- **Money precision** - all API values in integer cents; UI converts for display only; BigInt throughout the financial engine prevents floating-point drift
- **Demo vs. production auth** - `VITE_MOCK_MODE=true` bypasses Cognito for local demos; production builds require full Cognito JWT on every route except `/health`
- **Schema correctness under LLM variance** - two bounded Nemotron attempts (initial + schema correction); invalid output is reported as an error, never fabricated
